# Спецификация GreaterBash

[English](SPECIFICATION.md)

Документ описывает язык, который принимает GreaterBash, и поведение шелла. Он соответствует реализации в этом репозитории.

## 1. Обзор

GreaterBash - интерактивный Unix-шелл. Каждая введённая строка проходит четыре стадии:

1. **Лексический анализ** - строка делится на токены (слова, операторы, скобки).
2. **Разбор** - токены превращаются в абстрактное синтаксическое дерево (AST).
3. **Подстановки** - раскрываются переменные и арифметические выражения, снимаются кавычки.
4. **Исполнение** - обход AST; процессы создаются через `fork`/`exec`, соединяются конвейерами и перенаправлениями и объединяются в задания.

## 2. Лексическая структура

| Токен        | Значение                                   |
|--------------|--------------------------------------------|
| слово        | имя команды, аргумент, имя файла, флаг     |
| `\|`         | конвейер                                   |
| `\|&`        | конвейер для stdout и stderr               |
| `;`, перевод строки | последовательное выполнение         |
| `&&`         | выполнить следующую, если предыдущая успешна |
| `\|\|`       | выполнить следующую, если предыдущая неуспешна |
| `&`          | запуск в фоне                              |
| `(` `)`      | группа                                     |
| `>` `>>`     | stdout в файл (перезапись / дописывание)   |
| `&>` `&>>`   | stdout и stderr в файл (перезапись / дописывание) |
| `<`          | stdin из файла                             |
| `#`          | комментарий до конца строки                |

Пробелы и табуляции разделяют токены и в остальном игнорируются.

### 2.1 Кавычки

| Форма     | Поведение                                                          |
|-----------|--------------------------------------------------------------------|
| `'text'`  | текст как есть, без подстановок                                    |
| `"text"`  | пробелы сохраняются, `$VAR` и `$((...))` раскрываются              |
| `\x`      | экранирует следующий символ                                        |

## 3. Грамматика

```text
list       := item { (";" | NEWLINE | "&" | "&&" | "||" | "|" | "|&") item }
item       := command | "(" list ")"
command    := WORD { WORD | redirection }
redirection:= (">" | ">>" | "&>" | "&>>" | "<") WORD
```

Группа `( ... )` - один элемент, она может стоять везде, где допустима команда, например внутри конвейера.

### 3.1 Приоритеты операторов

От самого слабого к самому сильному, как реализовано в `main/src/parser.c`:

| Уровень | Операторы        |
|---------|------------------|
| 1       | `;` перевод строки |
| 2       | `\|` `\|&`       |
| 3       | `&&` `\|\|`      |
| 4       | `&`              |

Операторы одного уровня левоассоциативны. Завершающий `&` после простой команды запускает её в фоне.

> **Замечание.** В POSIX-шеллах `|` связывает сильнее, чем `&&` и `||`. Здесь наоборот, поэтому `a | b && c` разбирается как `a | (b && c)`. Чтобы получить POSIX-смысл, используйте группу: `(a | b) && c`.

## 4. Подстановки

Подстановки выполняются после разбора для каждого слова.

### 4.1 Переменные

| Форма       | Значение                       |
|-------------|--------------------------------|
| `$NAME`     | значение переменной шелла или окружения, пусто, если не задана |
| `$?`        | код возврата последней команды |
| `$$`        | PID шелла                      |
| `$!`        | PID последнего фонового задания |

Переменные создаются словом-присваиванием (`NAME=value`) или встроенными `set` и `export`.

### 4.2 Арифметика: `$(( выражение ))`

Вычисления идут в числах с плавающей точкой отдельным лексером, парсером и вычислителем (`math_parser/`).

| Элемент        | Детали                                              |
|----------------|-----------------------------------------------------|
| операторы      | `+` `-` `*` `/` `^` (степень), унарные `-` и `+`    |
| группировка    | `( ... )`                                           |
| константы      | `pi` (3.14), `e` (2.7)                              |
| функции        | `abs(x)`, `sin(x)`, `cos(x)`, `log(x)`, `pow(x, y)` |

Пример: `echo $((pow(2,8) + abs(0-5)))` выведет `261`. Деление не целочисленное: `$((10/4))` равно `2.5`.

## 5. Перенаправления

| Синтаксис   | Действие                                     |
|-------------|----------------------------------------------|
| `cmd > f`   | stdout в файл `f` с перезаписью              |
| `cmd >> f`  | stdout дописывается в `f`                    |
| `cmd < f`   | stdin из файла `f`                           |
| `cmd &> f`  | stdout и stderr в `f` с перезаписью          |
| `cmd &>> f` | stdout и stderr дописываются в `f`           |
| `a \| b`    | stdout `a` на stdin `b`                      |
| `a \|& b`   | stdout и stderr `a` на stdin `b`             |

## 6. Управление заданиями

- Каждый конвейер выполняется в своей группе процессов.
- Foreground-задание получает терминал (`tcsetpgrp`); шелл забирает его обратно, когда задание завершилось или остановлено.
- `cmd &` запускает фоновое задание; шелл выводит `[id] pid &`.
- Состояния задания: работает в фоне, остановлено, завершено, прервано.
- Завершённые дочерние процессы собираются в обработчике `SIGCHLD`.
- Сам шелл игнорирует `SIGINT`, `SIGTSTP` и `SIGTTOU`; дочерние процессы получают стандартную обработку сигналов.

## 7. Встроенные команды

| Команда                  | Описание                                                 |
|--------------------------|----------------------------------------------------------|
| `cd [dir]`               | сменить каталог; без аргумента - в `$HOME`               |
| `exit`, `quit`           | выйти из шелла                                           |
| `jobs`                   | список заданий                                           |
| `fg [id]`                | вывести задание на передний план                         |
| `bg [id]`                | продолжить остановленное задание в фоне                  |
| `kill pid [-SIG]`        | отправить сигнал; `-SIG`: `-TERM` (по умолчанию), `-INT`, `-STP`, `-CONT`, `-KILL` |
| `set NAME [value]`       | создать или изменить переменную шелла                    |
| `unset NAME...`          | удалить переменные шелла                                 |
| `export NAME[=value]`    | поместить переменную в окружение                         |
| `unexport NAME`          | убрать переменную из окружения                           |
| `history`                | вывести историю команд                                   |
| `help`                   | вывести справку                                          |
| `67`                     | пасхалка                                                 |

`echo` и `pwd` не являются встроенными, используются внешние программы.

## 8. Интерактивный режим

- Формат приглашения: `user@host:каталог$ `, `$HOME` сокращается до `~`.
- Редактирование строки (raw-режим терминала): стрелки влево/вправо, стрелки вверх/вниз для истории, Backspace, Ctrl+D на пустой строке для выхода.
- История хранится в памяти (до 500 записей) и между сеансами сохраняется в `~/bash_history.txt`.

## 9. Известные ограничения

- Приоритеты операторов отличаются от POSIX-шеллов (раздел 3.1).
- Не реализованы: подстановка `$(команда)`, глоббинг, here-documents, функции шелла, конструкции `if`/`for`/`while`, алиасы.
- `pi` и `e` - константы с низкой точностью (3.14 и 2.7).
- Только Linux: используются `termios`, группы процессов и `tcsetpgrp`.
